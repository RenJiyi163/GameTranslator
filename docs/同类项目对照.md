# 同类项目对照

2026-10-23 检索。星数、推送时间取自 GitHub REST API 当日返回值。非 GitHub 的闭源工具取其官方站点。

## 结论

有同类项目，而且不止一个。按功能集合算，这个项目是在重复造轮子：Unity 有 XUnity，视觉小说有 LunaTranslator，RPG Maker 实时翻译有 Live Translator，多引擎提取写回有 Translator++ 与 OctopusBridge，批量翻文本有 AiNiee，Ren'Py 有引擎自带方案。

不重复的部分只有一处能站住：**Electron / HTML 文本游戏**。MTool 官方列出的引擎里没有 Electron 也没有 HTML；LunaTranslator 走的是各 VN 引擎的 hook；GitHub 上以 CDP 通用注入处理 Electron 游戏的同类项目，检索没找到。

如果目标只是把一款游戏玩成中文，现成工具更省事，按引擎对号：

| 游戏类型 | 现成选择 |
|---|---|
| Unity | XUnity.AutoTranslator（接 BepInEx） |
| galgame / 视觉小说 | LunaTranslator |
| RPG Maker 全系（含 XP、VX Ace） | MTool |
| 想产出可分发的汉化补丁 | Translator++ |
| 批量翻导出的文本文件 | AiNiee |
| Ren'Py | LunaTranslator 内嵌，或 Ren'Py 自带 translate |

## 四类工具的差别

**闭源全家桶（MTool、Translator++）** 覆盖的引擎最多，安装最省事。代价在于改不了、不能自己接后端之外的逻辑，MTool 还要订阅。

**开源运行时注入（XUnity、Luna、Live Translator）** 不改游戏文件，截获出字函数。这条路线的成熟度差别很大：XUnity 在 Unity 上做了多年，Luna 的 hook 库覆盖几乎所有 galgame 引擎；Live Translator 只做 MV/MZ 一个引擎，而且要求玩家自己把 nw.js 换成新版。

**开源离线批量（AiNiee、OctopusBridge、Translator3000）** 先提取、再批量翻、再写回。质量可控、可以人工过一遍，代价是改动游戏文件，翻错会直接坏档。OctopusBridge 的 README 也承认 Twine 这条线常有崩溃和译文损坏。

**引擎官方（Ren'Py translate）** 最稳，但要求游戏脚本可读，产物是要分发的一整套语言文件，不能边玩边生成。

## 与 GameTranslator 0.2.3 的差异

以下逐条对照本项目 README 里写明的实现与上表的事实。

1. **Electron / HTML 文本游戏**。本项目用 CDP 附加，页面里跑通用 MutationObserver，选择器写在 profile。上表里没有第二个覆盖这一类的，MTool 官方引擎列表没有 Electron 与 HTML。这是实际空档。
2. **不改游戏目录**。Ren'Py 靠 `RENPY_SEARCHPATH` 从外部目录注入，MV/MZ 在内存里挂钩子。Luna 的内嵌同样不改文件，所以这一条不是独有，只是本项目覆盖的引擎里都做到了。
3. **词库优先、后端可关**。三档策略（只查词库、词库优先后端兜底、全走后端），只查词库时完全不调模型。Translator++ 与 OctopusBridge 有翻译记忆，但都把机翻当主路径；本项目的默认路径是查表，查不到才花钱。
4. **词库往返 Word**。未命中导出 docx，交给通用文档翻译服务，导回时做段落对齐、占位符与换行数校验，不合格的逐条写报告。检索到的工具里，MTool 用 `ManualTransFile.json` 交给 AiNiee，Translator++ 用自己的工程格式，没有见到走 docx 的。这条是相对于检索范围的差异，不能写成唯一。
5. **`.gtpack` 按游戏打包词库**。词库、术语表、配置打成一份可校验的包，导入时只并词库、保留本地配置。OctopusBridge 的翻译记忆是一台机器上跨项目的共享库，不做单款游戏的搬运。
6. **覆盖窄**。Unity 与 Unreal 只有适配器空壳（`unity_bepinex.py`、`unreal_ue4ss.py` 均为占位），而 XUnity 已经把这条路走完；RPG Maker 只做 MV/MZ，MTool 连 XP、VX Ace、2000/2003 都覆盖；Ren'Py 只覆盖对话、选项与引擎自带界面，Luna 的 hook 面更广。

结论落在第 1 条与第 3、4 条的组合上：填的是 Electron 文本游戏的空档，外加一套以人翻词库为中心的运行时查表流程。其余部分都有更成熟的现成实现。

## 未核实项

- MTool 启动游戏后是否往游戏目录写文件。官方教程只写到拖入、加载、开始翻译，社区教程称注入；本条没有实测。
- MTool 免费版与订阅版各能用哪些引擎。官方页面只有「先下载体验，再决定是否订阅」。
- LunaTranslator 的缓存与词库机制。README 只列了功能，没有展开实现。
- Translator++ 的引擎列表里 YU-RIS、LiveMaker 两项来自更新日志与第三方教程，官方下载页没有逐条列引擎。
- AiNiee 的术语表与缓存实现。
